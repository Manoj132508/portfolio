Engineering principles

How I approach the work.

A compact set of choices that recur across the systems I build.

01 / Ground

Evidence before generation

AI output should be traceable to source material—or state clearly when the evidence is missing.

02 / Separate

Deterministic control

Scoring, policy, permissions, and consequential actions belong in testable code, not model prompts.

03 / Design

Clear system boundaries

Authentication, tenancy, service ownership, and data flow should be visible in the architecture.

04 / Prove

Test the risky path

Focus verification on the behaviours that carry trust, security, and product consequences.
